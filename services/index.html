How I work

Understand the constraint

Start with the site, the affected journey and the evidence. Separate a server limit from a front-end or application problem.

Prioritise useful work

Agree on the next step and its validation criteria, rather than treating every possible optimisation as necessary.

Validate the change

Use staging where possible, check the affected commerce flows and document the result.

Keep the release reviewable

Prepare release notes and a rollback path. Measurement should explain what changed and what remains uncertain.

  1. Technical assessment

    Define the affected journey and a repeatable baseline.

  2. Infrastructure analysis

    Check capacity, caching and operational responsibilities.

  3. Performance evaluation

    Trace loading, interaction and stability bottlenecks.

  4. Search & indexability

    Review crawl paths, canonical URLs and internal links.

  5. User experience

    Check content, navigation and important commerce flows.

  6. Measurement & validation

    Repeat the checks, document limits and plan recovery.

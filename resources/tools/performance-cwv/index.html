Choose the tool around the bottleneck

A useful performance stack begins with a diagnosis. Avoid installing several cache or optimisation plugins with overlapping responsibilities. Choose one main approach, validate it, then add delivery or monitoring tools where they address a demonstrated need.

  • High TTFB: investigate origin requests, cache behaviour, PHP work and database queries.
  • Slow LCP: inspect the main image or text resource, critical CSS and render-blocking requests.
  • Poor INP: investigate long tasks and interaction scripts, including third parties.
  • Layout shifts: reserve image and embed dimensions and review late-rendered content.

Diagnose, fix, validate, monitor

  • Diagnose: use field data where available and a repeatable laboratory setup.
  • Fix: address the largest demonstrated constraint before adding more tools.
  • Validate: repeat the measurement and test the affected user journeys.
  • Monitor: look for sustained results and regressions after content, plugin or template changes.

WooCommerce safety checklist

  • Keep cart, checkout, account and order confirmation pages dynamic where required.
  • Respect session cookies and logged-in behaviour.
  • Check delayed or deferred scripts against payment and cart functions.
  • Test add-to-cart, mini cart, coupons, shipping, payment and account pages.
  • Use staging and a recoverable backup before making risky changes.

Performance tools FAQ

Do I need several caching plugins?

Usually one primary caching approach is easier to reason about. Overlapping settings can make diagnosis and rollback harder.

Is Cloudflare safe for WooCommerce?

It requires appropriate configuration. Do not apply indiscriminate HTML caching to sessions, carts, checkout or account pages.

Should I fix LCP or INP first?

Prioritise the actual user impact and the strongest evidence. A slow server, a large image and long interaction tasks require different fixes.

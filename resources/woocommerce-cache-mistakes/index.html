WooCommerce Cache Mistakes (and How to Fix Them)

Understand WooCommerce caching failures, dynamic page exclusions, session behaviour and a practical checklist for cart and checkout validation.

Where a request can be cached

What usually breaks

  • The cart does not update or shows stale totals.
  • Checkout resets or payment submission fails.
  • Logged-in users receive inappropriate cached content.
  • Dynamic pricing, shipping or currency choices are stale.
  • Account pages expose the wrong state.

The rule behind the exclusions

If the response changes with a customer’s identity, session, cart or order state, a shared full-page cache must not serve that response indiscriminately. Correct behaviour may require bypassing cache or using a carefully designed variation strategy.

URL exclusions are only part of the configuration. Review cookies, headers and the actual behaviour of the host, CDN and application cache.

WooCommerce cache checklist

  • Exclude cart, checkout, account and order confirmation pages where dynamic responses are required.
  • Respect session and cart cookies; verify logged-in behaviour.
  • Check edge and origin cache rules together.
  • Validate payment scripts before enabling delay or defer settings.
  • Test real commerce flows after every change, using suitable test payments on staging.
  • Keep a rollback plan and compare the same workload before and after.

When to investigate further

If the store still behaves incorrectly with caching excluded, inspect application conflicts, database queries and integration requests. The checkout investigation service covers that focused diagnostic work.
